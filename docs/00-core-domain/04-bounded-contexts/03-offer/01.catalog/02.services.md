# Services

## TL;DR
Un **Service** es la definición operativa reusable de *qué* ofrecés y *cómo opera*.

- Vive en el **Catalog**.
- Es **estable** y reutilizable entre múltiples Listings.
- Define las **reglas operativas**: duración, precio base, buffers, form, policy.
- **No** define presentación comercial, media, visibilidad ni canales de distribución.
- Se vende/reserva a través de **Listings**.

> Regla mental:
> **Service = reglas operativas** (qué es + cómo funciona)
> **Listing = estrategia comercial** (cómo se presenta y distribuye)
> **Booking usa Service. Discovery usa Listing.**

---

## Separación Service / Listing (v1)

| Responsabilidad | Service | Listing |
|----------------|---------|---------|
| Duración | ✅ `durationMin` (fuente de verdad) | puede ajustar (ej: versión express) |
| Precio base | ✅ `basePrice` (fuente de verdad) | aplica modificadores (discount, bundle) |
| Buffers pre/post | ✅ `preBufferMin`, `postBufferMin` | — |
| Formulario de intake | ✅ `intakeForm` | — |
| Política de confirmación | ✅ `confirmationPolicy` | — |
| Location (dónde ocurre) | ✅ referencia al Place operativo | puede especificar place alternativo |
| Media (fotos/videos) | ❌ **no pertenece al Service** | ✅ aquí vive la media |
| Copy (título, descripción promo) | ❌ | ✅ |
| Tags / categoría / discovery | ❌ | ✅ |
| Visibilidad / canales | ❌ | ✅ |
| Promociones | ❌ | ✅ modificadores de precio |

### Precio: fuente de verdad y modificadores

```
Service.basePrice       →  fuente de verdad
Listing.priceModifiers  →  delta (discount, bundle, dynamic — futuro)
                            ────────────────────────────────────────
EffectivePrice          =  basePrice + modifiers
Booking.priceSnapshot   =  EffectivePrice al momento de la reserva
```

Cambios en `basePrice` **no modifican** Bookings ya confirmados (snapshot protege al usuario).

## Media (decisión v1)

**La media (imágenes y videos) pertenece al Listing, no al Service.**

Razones:
- Permite múltiples Listings con diferentes visuales para el mismo Service.
- Mantiene los dominios operativo y comercial limpios.
- Habilita A/B tests y creatividades de campaña por Listing.

**Regla de UX (importante):**
La pantalla "Crear Service" puede incluir upload de imágenes para mejor UX.
Internamente, esa media se almacena en el **Listing** auto-creado, no en el Service.
El Service permanece libre de media a nivel de modelo de datos.

## Lifecycle

```
[Draft] ──activate()──▶ [Active] ──archive()──▶ [Archived]
   │                       │
   └── update() ───────────┘  (edición permitida en Draft y Active)
```

| Estado | Descripción |
|--------|-------------|
| **Draft** | Configuración incompleta. No genera Slots ni acepta Bookings. Editable. |
| **Active** | Completo y operativo. Puede generar Slots y aceptar Bookings. |
| **Archived** | Discontinuado. Solo preserva histórico. Read-only. No admite nuevos Listings. |

### Reglas de transición

- `Draft → Active`: requiere todos los campos requeridos válidos.
- `Active → Archived`: siempre permitido; Bookings existentes se preservan.
- `Archived → Active`: **no permitido** (debe crearse un nuevo Service).
- **Eliminar**: solo si el Service no tiene Bookings. Soft delete recomendado.

---

## Invariants

1. Un Service pertenece a exactamente un Profile.
2. `name` no puede ser vacío.
3. `durationMin` > 0 para activar.
4. `basePrice` ≥ 0 para activar.
5. `location` y `confirmationPolicy` requeridos para activar.
6. Un Service no puede eliminarse si tiene Bookings asociados.
7. Cambios en Service Active no modifican Bookings existentes ni recalculan Slots retroactivamente.
8. Solo Services Active admiten nuevos Listings.
9. Service no almacena media (pertenece al Listing).

---

## Qué NO debe ir en Service

- ❌ **Media** (fotos/videos) → pertenece al Listing
- ❌ Copy de marketing / descripción promo → pertenece al Listing
- ❌ Tags de discovery / categoría comercial → pertenece al Listing
- ❌ Visibilidad y canales → pertenece al Listing/Channels
- ❌ Modificadores de precio (descuento, promo, bundle) → pertenece al Listing
- ❌ Reglas de slots / disponibilidad proyectada → Timeline + Conflict Rules
- ❌ Auto-asignación / capacity pools → Listing + Assignment

## Ejemplos de modelado

### Médico con dos modalidades
```
Service: "Consulta"
  basePrice: 5000
  durationMin: 30
  confirmationPolicy: AutoConfirm

Listing A: "Consulta presencial"
  Place: consultorio
  modifier: +0

Listing B: "Consulta urgente"
  modifier: +2000
  copy: "Turno prioritario, misma semana"
```

### Estética nails
```
Service: "Capping"
  durationMin: 90
  basePrice: 8000
  preBufferMin: 5, postBufferMin: 10

Services: "Manicura", "Gel"
  (cada uno con su durationMin y basePrice propio)

Listings: definen promociones, canales, copy y media por campaña
```
