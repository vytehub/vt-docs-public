# Listings (Overview)

## TL;DR
Un **Listing** es la pieza comercial de VyteMerge: define **cómo** se vende u ofrece algo.

- **Service/Product** = *qué es* (definición reusable; “Servicios y Productos”)
- **Listing** = *cómo se vende* (precio, reglas, visibilidad, scheduling, media)
- **Booking/Order** = la transacción (reserva o compra)
- **Timeline/Place** = cuándo / dónde (si es reservable)

Los Listings son lo que aparece en:
- feed / marketplace
- channels
- campaigns (sponsored)

---

## Tipos de Listing
### Service Listing (reservable)
- genera **Slots** (disponibilidad proyectada)
- admite **Bookings**
- al confirmar Booking, crea un **Event** linked a los timelines relevantes (ADR-0006)
- puede ocurrir en un **Place**
- puede tener **Capacity / MinToConfirm / Attendees**

### Product Listing (comprable)
- admite **Orders**
- (futuro) inventario, variantes, fulfillment

---

## Qué problema resuelve
El mismo Service/Product puede venderse de formas distintas sin duplicar definiciones:
- “Masaje” → listing estándar
- “Masaje 2x1” → listing promo
- “Masaje express” → listing corto
- “Shampoo” → listing regular / pack

---

## Relación con otros módulos
- **Servicios y Productos**: fuente del “qué”
- **Timelines + Conflict Rules**: fuente del “cuándo”
- **Places**: fuente del “dónde” y zona horaria
- **Bookings / Attendees**: reservas (service listings)
- **Orders**: compras (product listings)
- **Agreements + Access**: quién puede ver/hacer qué
- **Feed / Channels / Campaigns**: distribución
