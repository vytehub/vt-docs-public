# Basic Properties

## Qué define este documento
Lo mínimo que necesita un Listing para existir como “pieza comercial”:
- qué referencia (Service/Product)
- cómo se presenta (título, descripción, media)
- estado/lifecycle básico (draft/published)
- visibilidad mínima (público/privado) *sin entrar todavía en canales*
- (opcional) composición simple mediante **Add-ons**

---

## Identidad del Listing
Campos típicos:
- `ListingId`
- `OwnerProfileId`
- `Type`: `ServiceListing` | `ProductListing`
- `SourceId`: `ServiceId` o `ProductId`
- `Title`
- `Description`
- `Status`: Draft | Published | Archived
- `AddOns` (opcional): productos o extensiones de servicio ofrecidas junto al listing

---

## Composición (simple)
Un Listing normalmente vende **una** cosa (un Service o un Product), pero puede incluir **Add-ons** para:
- aumentar el valor del booking/checkout
- armar promociones sin duplicar servicios

Tipos de add-ons:
- `Product Add-on`: agrega un producto al checkout.
- `Service Extension Add-on`: agrega duración/precio **dentro de la misma cita**.

> Las reglas de duración efectiva, precio total y restricciones viven en el documento **Add-ons & Bundles**.

## Media y Cover (regla oficial)
**Regla simple:**
1) Si el Listing tiene media → se usa esa media.
2) Si NO tiene media → se usa la media del Service/Product como fallback.

### Por qué
- Service/Product media es “default” (reusable).
- Listing media es “de esta oferta” (promo, canal, variante).

### Ejemplos
- Service: “Masaje” con fotos genéricas.
- Listing: “Masaje 2x1” con flyer específico.
  - En feed/campaigns se muestra el flyer (listing cover).
  - Si el listing no tuviera flyer, se verían las fotos del service.

### ¿Y si quiero “usar las fotos del service + agregar una más”?
**MVP recomendado: Copy.**
- UX: botón “Copiar fotos del servicio” al listing.
- Luego el listing puede agregar/quitar fotos libremente.

> Evitamos una regla “merge” automática que genera edge cases (orden, cover, removals).

## Visibilidad mínima (placeholder)
A nivel listing, como mínimo:
- `Visibility`: Public | Private

La gobernanza fina vive en:
- **Access** (enforcement)
- **Channels** (audiencias)
- **Agreements** (relaciones formales)

---

## Defaults recomendados (MVP)
- Si no se especifica media del listing → fallback a service/product.
- Status inicial: Draft
- Publicación manual: Published
- Private default para listings “internos” (ej: staff/partner) y Public para marketplace (según UX).
