# Templates

## TL;DR
Las **Templates** permiten estandarizar y personalizar mensajes por canal (Email/Push/SMS/WhatsApp) sin escribir texto manual en cada booking.

- Se definen **a nivel Owner (Profile/Organization)** como defaults.
- Se pueden **overridear** a nivel Listing (opcional) y excepcionalmente a nivel Booking.
- Cada envío guarda un **snapshot** del contenido final (auditoría y soporte).

---

## 1. Por qué separar Templates de Reminders
Reminders define **cuándo** y **por qué** se envía algo.  
Templates define **qué texto** se envía.

Separarlo evita:
- lógica mezclada en bookings
- mensajes inconsistentes
- problemas de compliance (“qué texto se envió realmente”)

---

## 2. Estructura conceptual (MVP)

Una template tiene:
- `TemplateId`
- `OwnerProfileId`
- `Kind` (ReminderUpcoming, BookingConfirmed, BookingCancelled, etc.)
- `Channel` (Email/Push/SMS/WhatsApp)
- `Language` (es-AR, en-US, etc.) *(opcional MVP)*
- `Subject` (solo Email)
- `Body` (texto con variables)
- `IsActive`
- `Version` o `UpdatedAtUtc`

> MVP: empezar con 2–3 kinds: UpcomingReminder + BookingCancelled + BookingRescheduled.

---

## 3. Variables permitidas (safe variables)

### Reglas
- Las variables deben ser **whitelisted** (lista permitida).
- El render debe ser **fail-safe**: si una variable no existe → reemplazo vacío o fallback (sin romper el envío).
- Respetar **Access/VisibilityMode**: si el destinatario no puede ver un dato, no se renderiza.

### Variables típicas
- `{clientName}`
- `{ownerName}`
- `{listingTitle}`
- `{serviceName}`
- `{date}`
- `{time}`
- `{location}`
- `{actions.confirmUrl}`
- `{actions.rescheduleUrl}`
- `{actions.cancelUrl}`

> Evitar variables “sensibles” por default (ej: notes internas, diagnósticos, etc.).

---

## 4) Snapshot y auditoría (importante)
Cuando se envía una notificación, se guarda:
- `TemplateId` + `TemplateVersion` (o `UpdatedAt`)
- `RenderedSubject` y/o `RenderedBody`
- `RecipientId`
- `Channel`
- `SentAtUtc`
- `ProviderMessageId` *(si existe)*

Esto permite:
- soporte (“qué se envió”)
- auditoría legal/comercial
- debugging

---

## 5. UX sugerida (simple)
- Pantalla “Mensajes”:
  - tabs por canal (Email/Push/SMS/WhatsApp)
  - selector de tipo (Reminder, Cancelación, Reprogramación)
  - editor con chips de variables
  - preview
  - botón “Restaurar default”
